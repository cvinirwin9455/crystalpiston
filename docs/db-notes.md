## Schema quirks (read before counting / filtering users)

- **Coaches are NOT `role='coach'`.** The `users.role` column never uses the value `'coach'`.
  A coach is stored as:
  - `role = 'admin'` **and** `coach_level IS NOT NULL`
  - `coach_level = 'coach'` → a regular coach
  - `coach_level = 'account_coach'` → the organization owner / primary coach
  - ✅ Correct way to count coaches: `WHERE coach_level IS NOT NULL` (or `WHERE role='admin'`).

- **`has_coach_access = true` means dual-role**, not "is a coach."
  It flags a `role='client'` account that *also* has coach access (the dual-role feature:
  one login that is both a client and a coach). Do not use this to count coaches.

- **Clients:**
  - `users.role = 'client'` counts client-role logins.
  - The `clients` table holds the actual client *profile* (goal, start_date, billing_mode, etc.),
    linked by `clients.user_id -> users.id`. Not every client-role user has a `clients` row
    (e.g. pending invites), so these two counts can differ.

- **Status:** `users.status` is `'active'` / `'inactive'`. Archived/soft-deleted clients are
  flipped to `'inactive'` rather than deleted.

- **Organizations:** multi-tenant. Rows carry `organization_id`. Staging has a single org
  (`00000000-0000-0000-0000-000000000001`). Some stray test rows have `organization_id = null`.

## Running read-only queries

Use the helper script (read-only guard built in — refuses anything but SELECT/WITH/EXPLAIN/SHOW):

```bash
# load Node (nvm) first in each new shell
export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"

node .db-query.mjs "SELECT count(*) FROM users WHERE coach_level IS NOT NULL"
```

The helper reads `STAGING_DB_URL` from `.env.local`.

### Example: count coaches vs clients (the correct way)

```sql
SELECT
  (SELECT count(*) FROM users WHERE coach_level IS NOT NULL) AS coaches,
  (SELECT count(*) FROM users WHERE role='client')          AS clients_by_role,
  (SELECT count(*) FROM clients)                            AS client_profiles;
```

As of last check, staging had **3 coaches** (Crystal, Adam, Curtis/account_coach) and ~23
client-role users (mostly test accounts; ~18 with full profiles).
